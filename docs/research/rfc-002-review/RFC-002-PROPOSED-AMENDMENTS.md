# RFC-002 — proposed amendments from the independent review

**Status.** These are proposals to the RFC author. RFC-002 itself has **not** been edited. Each amendment gives the original proposal, the objection, the evidence, the proposed text and the trade-off. Priority: **P** = required before approval; **S** = should, before the gate it affects.

| # | Pri | RFC § / decision | Original proposal | Objection | Evidence | Proposed amendment | Trade-off |
|---|---|---|---|---|---|---|---|
| A1 | P | §4, §6 / D01, D02, D03 | `PathObject { geometryRef }`; "immutable geometry buffers"; history capped by uniquely retained bytes | Granularity is unspecified. Per-object buffers make a 30k-path trace 30k transferables; per-layer buffers make one-object edits copy whole layers and make the byte cap meaningless | Real traces: 1 to 29,944 paths; a halftone is one 195k-subpath path [measured R01] | Introduce **immutable geometry chunks**: one per trace commit or bake. Objects reference `(chunkId, pathIndex)`; geometry edits create small new chunks; transforms, styles and visibility never copy geometry; chunks are refcounted by document, history and pending jobs | Indirection in the store; chunk compaction needed later for heavily edited documents |
| A2 | P | §6 / D01, D03 | "Committed buffers never detached" (prose) | Typed arrays cannot be frozen; transferring a committed buffer silently destroys it | Detachment demo: `coords.byteLength` 0 [measured R01] | A **GeometryStore API** that never exposes committed `ArrayBuffer`s; `jobCopy()` is the only route to a transfer list; tests assert it | Every worker send costs one copy (measured ~1.6 ms per 45 MB) |
| A3 | P | §6 / D03 | Binary bridge "conditional"; "capped v1 JSON fallback for small scenes" | Two editor transports double validation and test surface for no benefit | JSON and packet are about the same size; main-thread parse 97–198 ms vs validate 8–20 ms at ~1M anchors; packet delivery 0–10 ms [measured R01] | GeometryPacket v1 is the **only** editor transport and storage format for geometry; scene v1 JSON stays the export and interop format through an adapter | Debugging needs a small dump tool instead of reading JSON |
| A4 | S | §6 / D03 | Packet carries "bounds" | Derived data adds a consistency check and attack surface | The single validation pass derives per-path bounds and subpath starts at no extra pass [measured] | Do not transport derived data; validation derives bounds, subpath starts and anchor count; `groupIndex` must be non-decreasing | None measurable |
| A5 | P | §6 / D03 | "Validate … in both languages" | No conformance suite is named | The first adversarial run found an offset bounds gap in the prototype validator [measured] | A shared adversarial suite (27 cases: `adversarial.mjs`) for the TS and Rust validators, including manifest budget checks **before allocation** | Maintenance of the shared fixtures |
| A6 | P | §7 / D04 | Retained Canvas 2D first candidate, conditional on R02; "incremental invalidation"; caches optional | Canvas is right, but only with parts the RFC leaves optional or unstated | Exact redraw misses the budget at ≥ 300k in Firefox and WebKit (per-`fill()` 5 / 2.3 µs). With the display cache: gestures p95 17–22 ms in 3 engines up to 1M. With the OffscreenCanvas host: main-thread gaps ≤ 24 ms in 3 engines; one `fill()` of the 977k halftone takes 174–251 ms in WebKit. Grid ≈ STR; the subpath index is required (12.8 ms → 0.0005 ms) [measured R02] | **D04: Canvas 2D, decided.** Mandatory: (1) a display-only raster cache for gestures, with exact redraw on settle and layered caching for drags; (2) host the renderer in an OffscreenCanvas render worker (the same renderer on the main thread as a disclosed fallback); (3) a renderer-independent hit-test service (uniform grid, subpath index for paths with more than 8 subpaths, band index for huge subpaths, pre-flattened typed arrays); (4) a progressive first frame. Limits: interactive ≤ 250k anchors and ≤ ~40k paths; stress 500k–1M with exact redraw labelled; product cap 1M unchanged. Revisit WebGL2 or WebGPU (tessellated and batched) under the conditions in RENDERER-EVALUATION §9 | A second geometry copy in the worker (≈ 45–52 MB per 1M anchors); the exact settle redraw is visible latency (off the main thread) at 500k–1M in Firefox and WebKit |
| A7 | P | §7 / D04 | (not addressed) path construction method | Chromium builds Path2D incrementally (`moveTo`/`bezierCurveTo`) in quadratic time | 250k anchors in one path: 16.9 s, vs 30 ms via path data and 8 ms via `addPath`; Firefox and WebKit linear [measured] | Renderer contract: construct paths from SVG path data or chunked `addPath`; a scaling regression benchmark in G-R0 | String building costs about 0.1–0.4 µs per anchor |
| A8 | P | §8 / D05 | "Explicit Apply/final/export higher priority than … preview" | Does not say which jobs may be terminated, and termination is the only cancel. The P0 client terminates workers during start-up | WebKit offline: 14/16 checks, deterministic, when workers are terminated during module load; 16/16 after the fix [measured R03] | Normative scheduler contract (R03 §2): **only previews are pre-emptible**; finals and exports are cancelled only explicitly; **never terminate a worker before its job is posted**; requeue a job once on start-up failure; acceptance requires current generation and running job ID; commit only after a revision check | Slightly longer worst-case preview latency while a final or export runs (by design) |
| A9 | P | §8 / D05 | Protocol "version handshake, generation, jobId, document revision…" | Agree; make it fail-closed | R03 stale-error and late-result drops [measured] | Every result and error echoes `jobId` and `generation`; anything else is dropped and counted | — |
| A10 | P | §13 / TD-PERF-002 | "Early cost estimate after segmentation, before expensive fitting" | Segmentation **is** the expensive part for colour, so a post-segmentation estimate cannot meet "report within 2 s" | Segmentation 66–99 % of colour trace time; post-segmentation predictor 0 FP / 0 FN; preview forecast 2 FP / 1 FN, 18 % median error [measured R03] | Two-stage policy: **forecast** from the ~1 MP preview trace (warn with a range and explicit choices, never auto-reject); **fail before fitting** on the post-segmentation estimate. Needs a staged engine API, which replaces the `segment_layers` diagnostic | The 2 s criterion is met as a forecast, not a guaranteed decision: an owner decision |
| A11 | P | §9 / D06 | Trace-local shared topology; label vs graph to compare in R04 | Option A is insufficient; the metric needs restating | Oracle labels remove 76–81 % of slivers but fail curvature; the graph prototype gives exact partitions and 0 slivers on 6 fixtures; the registered metric flags analytic truth [measured R04] | Adopt R04 §8: graph in the Rust evaluation stage; stacked and mosaic from one edge set; junction-local correction plus a junction estimator; **precision v2 opt-in**; G-SB gate; independent paths at commit with digest-checked provenance; plates never coupled; owner ratifies the metric restatement | Engine complexity (one new subsystem); precision v1 must stay reproducible alongside v2 |
| A12 | S | §10 / D07 | Typed linear domains | Missing seams for halftone-in-shape, ink plates and seed stability | Feature walk-through [analysis] | Add side inputs by reference (digest-keyed), composite multi-output values (plates, groups) and seeds derived from **operation-instance IDs** | Slightly richer descriptor schema |
| A13 | S | §5 / D02 | Drag or slider transient, one commit on release | Keyboard sliders commit on every key | Base UI: 5 commits for 5 arrow keys [measured R05-A] | Coalesce consecutive commits to the same parameter (time window or focus change) into one history entry | Timing heuristic in the command layer |
