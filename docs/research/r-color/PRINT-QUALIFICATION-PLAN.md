# R-COLOR-10 — Print qualification strategy

Status: **plan**, 2026-11-25. Except for the prototype evidence listed in §6, **nothing below has been run.** No qualification result is claimed.

## 1. Three questions, never merged

| Level | Question | Evidence | Wording allowed after a pass |
|---|---|---|---|
| **Structural** | Is it a valid PDF/TIFF/PNG with the intended objects and metadata? | qpdf, object inspection, tiffinfo, PNG chunk dump | "structurally valid; contains output intent X" |
| **Colour accuracy** | Are the device values what the profile and intent prescribe, and do they render as expected? | reference CMM tables, CMYK-aware renderers, measured prints | "converted with <profile digest> / <intent>; ΔE00 ≤ N against reference" |
| **Standard conformance** | Does it conform to PDF/X-4 (or another standard)? | independent PDF/X validators | "PDF/X-4 verified by <tool, version>" |
| *(Acceptance)* | Did provider P accept and print it acceptably? | test order | "accepted by P on <date> for <product>" |

## 2. Qualification corpus

All inputs are synthetic, or public domain from `tests/fixtures/`. **No private photographs.** Corpus items are generated by scripts (like `experiments/r-color/cmm` `patches()` and `pdf_proto` `scene()`) so that no binaries need committing.

| ID | Content | Exercises |
|---|---|---|
| Q-01 | RGB primaries and secondaries, white, black | gamut edges, white and black rules |
| Q-02 | 17-step neutral grey ramp, and 0/1/2/254/255 near-limits | neutral axis, black generation, white snapping |
| Q-03 | Pure black `#000000` line art: hairline, 1 pt and 2 pt lines, small type-like shapes | K-only override, TAC, minimum features |
| Q-04 | Saturated and out-of-CMYK-gamut colours (the 6×6×6 cube; violet, green, cyan) | gamut warnings, intent differences |
| Q-05 | Limited palettes: 2-, 4- and 8-colour traces of public-domain fixtures | palette-table conversion, overrides |
| Q-06 | Opaque overlapping objects | knock-out semantics |
| Q-07 | Translucent overlapping objects (50 %, 25 %; 2 and 3 layers) | blending-space differences (measured 11.9–19.1 ΔE00) |
| Q-08 | Vector halftones (Old Print): fine pitch, 45° and rotated, near-solid | minimum dot, LPI, ink coverage |
| Q-09 | Multi-layer document with hidden and locked layers | evaluation (hidden nodes don't export) |
| Q-10 | Clipped groups, nested and axis-preserving (C8) | clip preservation |
| Q-11 | Complex vector artwork (about 1M anchors): synthetic scenes such as the review bench generator, or traces of public-domain fixtures; never the private regression photographs | size, time, memory |
| Q-12 | Embedded sources: sRGB, Display P3, Adobe RGB, cICP, gAMA, CMYK JPEG; plus untagged | decode classification ([ICC-PROFILE-LIFECYCLE §3](ICC-PROFILE-LIFECYCLE.md)) |
| Q-13 | Missing profile (digest relink), wrong profile class, monitor profile offered as output | lifecycle errors |
| Q-14 | Malformed ICC corpus (seeded mutations, as in `icc_fuzz`) plus published fuzz reproducers | validation, no crash, typed errors |
| Q-15 | Spot ink plate set: 3 inks, knock-out, trap 0.2 mm, registration marks | Separations, plates |
| Q-16 | Physical patch sheet: the Q-01..Q-04 patches as 10 mm squares, plus ink-limit and rich-black ladders | physical print measurement |

## 4. Acceptance criteria (proposed, with rationale)

Thresholds are proposals for owner approval, derived from the margins measured in this research. They are not universal print tolerances.

| # | Criterion | Threshold | Rationale and evidence |
|---|---|---|---|
| A1 | Engine agreement: production CMM vs Little CMS, same profile, intent, no BPC, over Q-01..Q-05 | ΔE00 mean ≤ 0.5, p95 ≤ 1.0, max ≤ 2.0 | measured moxcms vs Little CMS: 0.046 / 0.149 / 0.673 (tetrahedral 0.031 / 0.101 / 0.281). ColorSync vs Little CMS 0.35 / 0.85 / 1.27. The thresholds leave headroom for registered profiles, which are larger LUTs |
| A2 | Native vs WASM device values (export path) | 8-bit: identical; 16-bit: ≤ 1 LSB; PDF bytes identical **per target** | measured 1,028/1,028 identical at 8-bit; 1,026/1,028 at 16-bit (Δ 1); f32 not identical (FMA) |
| A3 | White rule | `#ffffff` → no ink (0/0/0/0) when "white = paper" | engines give 0/0.4/0.4/0; a printed tint is a visible defect |
| A4 | Black rule | K-only override exact (0/0/0/100); rich black only by explicit recipe | measured ICC black 72/70/64/87 (294 %) |
| A5 | Total ink | max TAC ≤ the preset's limit after overrides; report the maximum | provider limits 240–300 %; generic profile reaches 294 % |
| A6 | Gamut warning | flag patches whose round-trip ΔE00 > 2.0; report the count | agreed with Little CMS's gamut check on 240/257 patches |
| A7 | Geometry | colour-free path-operator sequence identical to the RGB export (except the declared bleed extension) | measured identical (prototype) |
| A8 | Structure | `qpdf --check` clean; 0 images and 0 fonts in vector exports; boxes as requested; no DeviceRGB under a CMYK intent; poppler parses without "Syntax Error" | poppler caught a content bug that qpdf did not (prototype) |
| A9 | CMYK render vs proof (opaque patches) | ΔE00 ≤ 1.5 with a renderer that applies the output intent | Quartz measured ≤ 1.4; poppler up to 4.5 (does not use the intent): unsuitable |
| A10 | Translucency | reported count of translucent items; the soft proof shows the CMYK composite, within ΔE00 ≤ 2 of the CMYK-aware render | measured CMYK composite vs renders 1.2–5.9 (renderer RGB output, 8-bit sampling); tighten after Ghostscript is available |
| A11 | Raster | pixel size = round(size × ppi / unit); resolution metadata exact; embedded profile digest as requested; band render identical to a full render; bytes identical per target | measured exact 300 ppi and deterministic bytes in-process. Across runs, the PNG changed because a run-time-generated profile embeds its creation time (fixed by committing the profile). Band identity NOT RUN |
| A12 | Profiles | 0 crashes or panics on Q-14; structural rejects with typed errors; sanity checks pass for valid profiles | 4,000 measured cases: 0 crashes, but both engines accept corrupt data |
| A13 | PDF/X-4 | 0 errors in two independent validators; warnings dispositioned | [PDFX-FEASIBILITY §6](PDFX-FEASIBILITY.md) |
| A14 | Physical (Q-16) | measured patch Lab vs the profile's expected Lab: recorded, not pass/fail, until the owner sets tolerances per process | press, substrate and provider vary; the PDF/X and Ghent bodies leave quality to agreements |

## 5. Procedure

1. Generate the corpus at a fixed engine and app version. Record versions, profile digests and machine conditions.
2. Export every item in every colour kind under test.
3. Run A1–A12 automatically (native and WASM), storing JSON reports beside the files.
4. Run A13 for PDF/X candidates. Store the validator reports. Use the tool vendors' predefined profiles; no custom relaxation.
5. Run A14 through provider test orders: the patch sheet plus one artwork per product. Record order IDs, product, date, photographs or measurements. **Never generalise from one provider to another.**
6. Owner review. Only passed configurations become presets, and the wording follows §1.
