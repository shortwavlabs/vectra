# P1 architectural inputs (handoff to RFC-002)

This is a requirements-and-questions handoff, not RFC-002. It chooses no libraries and builds no abstractions. Evidence references point to P0/P0-R reports.

| Topic | Requirements carried forward | P0/P0-R evidence | Open questions for RFC-002 |
|---|---|---|---|
| Editable document vs evaluated scene | The document holds intent: objects, groups, layers, transforms, effect recipes, source references. The evaluated scene (P0 scene v1 or successor) is derived and is the only input to preview and export. The same scene feeds SVG and PDF. | Scene v1 is validated, versioned and deterministic. One validated scene drives both exports (P0-G3, P0-R-G3). | Where does evaluation run (WASM worker only, or partly JS)? What is the scene v2 delta (ids, clips, strokes)? Which document version and migrations? |
| Stable object ids | Ids assigned at commit; preserved across re-evaluation of unchanged inputs; never reused; deterministic for identical recipes. | P0 has group ids and palette ids only; traced paths have no identity. | Content-addressed ids, or allocated counters? How are ids matched when a re-trace changes topology? |
| Selection and hit testing | Hit testing on evaluated geometry with fill rule and holes, at interactive rates. Selection scopes: object, layer, palette colour, all. | Even-odd/nonzero semantics verified. Large scenes reach 555k anchors. | Main-thread geometry mirror vs WASM queries? Spatial index? Tolerance in screen vs document units? |
| Groups and layers | Ordered layers, nested groups, visibility, lock; the source raster is a locked reference layer excluded from export. Ink plates are groups. | Scene groups are ordered; clips are rectangles only. | Are layers a special case of groups? Plate semantics (CL-01) in the document or only in the evaluated scene? |
| Reversible transforms | Affine transforms in the document; baked into absolute coordinates in the evaluated scene (keeps exporters trivial). f64 in the document; round only at serialisation. | Scene v1 forbids transforms by design. Coordinates are quantised to 0.01 px. | Transform representation (matrix vs decomposed)? Numerical tolerance for bake equivalence? |
| Undo/redo commands | Atomic commands; gesture coalescing (sliders, brushes); "replace trace" never silent; bounded history memory. | P0 has no history. Rapid setting changes are already latest-wins. | Command vs snapshot granularity? Persisted history? How are large geometry payloads stored (structural sharing)? |
| Geometry across the JS/WASM boundary | Avoid JSON for large geometry; transfer typed arrays or keep geometry in WASM behind handles. Respect worker termination (handles die with the instance). | JSON scene plus SVG text works up to about 1 M anchors but costs parse time and memory (PERFORMANCE-BASELINE). Terminate-to-cancel discards WASM state. | Ownership model: worker-owned geometry plus main-thread render mirror? Serialization for persistence? |
| Large-scene rendering | Interactive pan/zoom/select on agreed hardware; preview equals export; no raster in export, though raster caches for display are allowed. | `<img>`-of-SVG preview paint is measured in PERFORMANCE-BASELINE. Multi-MB SVGs are common for halftone and limited colour at 12–24 MP. | Canvas 2D, WebGL or SVG DOM? Level-of-detail? Budget per frame? |
| Arbitrary path clipping | Clip to paths (alpha masks, ink shapes) for halftone-in-shape, screen print and Old Print contour ink; exported as vector clips (SVG `clipPath` with path, PDF `W n`). | Rect clips are already exported and verified in both formats. | Clip vs boolean intersection (bake)? Nested clips? |
| Independent ink plates | 1–3 named RGB plates, independent registration, seed, visibility and order; vector export in plate order; no spot or CMYK claims. | Groups plus palette ids exist; halftone is one ink. | Plate as layer type? Per-plate SVG export? |
| Multiple source images | Per-document source budget (total pixels, memory). Sources stay local and are excluded from export, with provenance. | Single source, 12 MP default cap, worker recycling above 1 GiB WASM memory, about 0.9 GiB at 24 MP. | Where are sources stored (memory, OPFS, IndexedDB)? Decode once and share across workers? |
| Typed procedural effect pipelines | Operations declare input/output domain, parameters, units, seed policy, resource estimate and cancellation behaviour. Type-checked ordering; explicit bake. | The P0 pipeline is fixed: pre-process → segment → fit → scene, plus halftone synthesis. | Operation registry location (Rust)? Caching of intermediates across edits? |
| Deterministic recipe evaluation | Same source RGBA + recipe + seed + engine version gives identical scene bytes. Versioned PRNG and distributions. | Byte-identical across runs and across macOS/Linux WASM builds (65/65 cases). Browser decoding differs, so determinism is "per decoded RGBA". | Move decoding into WASM? Declare per-browser determinism? |
| Worker scheduling and cancellation | Job kinds with priorities; bounded concurrency (e.g. variation thumbnails); stale-result rejection; recovery from crash and offline. | Single worker, latest-wins, terminate-and-recreate, versioned service worker (P0-R-G2). Cancel acknowledged in under 1 ms. | Cooperative cancellation (SAB+COEP) vs chunking vs terminate? Worker pool size vs memory? |
| Local project persistence | Explicit local saves; a bounded archive (manifest, sources, document, recipes); schema migrations; path-traversal and size limits. | None in P0. | OPFS vs downloads? Autosave policy? |
| `.vectra-preset` compatibility | A declarative recipe of allowlisted operations with bounded parameters, seed, schema version and engine range. No code, URLs or artwork. Free and paid packs use the same parser. | `TraceRequest` validates with `deny_unknown_fields` and explicit ranges, which is a precursor. | Schema versioning and migration? Compatibility ranges? Signature or none (no DRM, per BRAND)? |

## Non-negotiables to restate in RFC-002
- Local-only processing.
- No AI, accounts, subscriptions, DRM or paid-only engine features.
- Genuine vector export with no raster fallback.
- Strict CSP; online adapters isolated and opt-in.
- Explicit resource budgets with recoverable errors.
- Deterministic seeded operations.
- MIT core with generated third-party notices.
